## 一、今天为什么重要

Day8 你是用**网页**看车；今天用**命令行**直接和各话题打交道。
你 Day2 学的 `ros2 topic list/echo/pub` 今天全部原样复用——这就是"仿真学的东西能迁移到真机"的第一次实证。

四个必须通的话题：
| 话题 | 是什么 | 通了的表现 |
|---|---|---|
| `/cmd_vel` | 速度指令（你发给车） | 发了车动 |
| `/odom` | 里程计（车告诉你位置） | 轮子转，数值变 |
| `/scan` | 雷达点云 | `echo` 有距离数据 |
| `/battery` | 电池电压 | 有数值（有的镜像无此话题，正常） |

## 二、今天做什么

> 💻 **今日代码**：`chassis_health_check.py`（本目录）——把下面步骤 2/3 的命令行检查做成**一个常驻节点**，
> 订阅 `/odom` `/scan` `/battery_state`(兼容旧版 `/battery`)，每 1 秒打印"通/断/陈旧"体检报告。
> 运行：`python3 chassis_health_check.py`。它教的正是岗位 JD 反复要的"通信异常/传感器无数据故障排查"。
>想手敲命令熟悉话题的，按下面步骤走；想直接看自动化效果的，跑这个节点。

### 步骤 1 · 一键自检（本目录现成脚本）
```bash
# 先把脚本 scp 到车上
scp 真机环境自检.sh <用户名>@<车IP>:~/
# SSH 上车后跑
bash ~/真机环境自检.sh
```
脚本查 5 项：ROS2 版本 / 四个关键话题 / TF 树 / 雷达串口摄像头 / Domain 隔离。
🔴 全程**轮子架空**——脚本只检查不发速度，但保险起见架空。

### 步骤 2 · 手动通底盘（对照 Day2）
```bash
ros2 topic list                       # 应看到 /cmd_vel /odom /scan
ros2 topic echo /odom                 # 手动转轮子，看 x/y 变化
ros2 topic echo /scan --once          # 看雷达有没有距离数据
```

### 步骤 3 · 发速度让车动
```bash
ros2 topic pub --once /cmd_vel geometry_msgs/msg/Twist \
  "{linear: {x: 0.1}, angular: {z: 0.0}}"
```
✅ 车动 + `/odom` 变 = 底盘通了。转完记得发全 0 停：`{linear: {x: 0.0}, angular: {z: 0.0}}`。

### 步骤 4 · 键盘控制（视频 [1-9]）
用卖家的键盘控制节点遛车（架空或空地慢速）——这是 Day10 建图时要用的「走遍全屋」工具，今天先练熟。

### 步骤 5 · 检查 TF 树（为 Day10 铺路）
```bash
ros2 run tf2_tools view_frames        # 生成 frames.pdf
```
确认 `odom → base_link → laser_frame` 齐全。TF 断链会导致建图/导航全崩，今天先确认。

## 三、今天踩坑

- [ ] **发了 `/cmd_vel` 车不动** —— 轮子架空了没？`/odom` 变不变？电机使能了吗（有的车要单独启动底盘节点）？
- [ ] **`/odom` 不动** —— 编码器线松了，或底盘节点没起来（`ros2 node list` 看有没有）。
- [ ] **`/scan` 无数据** —— 雷达串口没识别；`ls /dev/ttyUSB*` 看设备，检查 `ros_config.json` 里的雷达端口。
- [ ] **TF 断链** —— `view_frames` 看哪段缺，补静态变换或起 `robot_state_publisher`。
- [ ] **`ROS_DOMAIN_ID` 串台** —— 车和 PC 用不同 domain；`echo $ROS_DOMAIN_ID`。
- [ ] **遥控器/中控台也在发 `/cmd_vel`** —— 别和你手动发的撞，先停一个。
