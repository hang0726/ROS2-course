## 二、你要做的 3 步（在**你自己的普通终端**，不是 agent 终端）

> 🔴 为什么改用 D 盘密钥：本机 `C:\Users\MicckeY\.ssh` 和 `.gitconfig` **连普通终端都写不进去**
> （`Permission denied`）。标准 `~/.ssh` 路线在本机彻底走不通，所以密钥已生成到 D 盘，
> 仓库也已配好 `core.sshCommand` 自动使用它 —— 你**不用再碰任何密钥生成命令**。

### 1. 读取已经生成好的公钥
在 PowerShell 里执行（路径是 D 盘，不是 Home）：
```powershell
Get-Content D:\ROS2Course\ssh\id_ed25519_v2.pub
```
复制输出的那整行 `ssh-ed25519 AAAA... hang0726@users.noreply.github.com`。

### 2. 把公钥贴到 GitHub
网页：**Settings → SSH and GPG keys → New SSH key** → Title 随便填（如 `laptop`）→ 粘贴公钥 → Add SSH key。

### 3. 推送（走 Windows 侧，零兼容问题）
```powershell
cd D:\ROS2七天速成
git push -u origin main
```
仓库已配 `core.sshCommand`，会自动用 D 盘私钥，**不会去读 Home 的 `.ssh`**，所以不需要任何 `safe.directory` 或额外配置。
推送完打开 <https://github.com/hang0726/ROS2-course> ，应能看到 Day1~Day7 全部文件夹和 README。

> 📌 密钥文件位置（记住即可，日常不用管）：
> - 私钥 `D:\ROS2Course\ssh\id_ed25519_v2` —— **绝不外传、不提交进仓库**
> - 公钥 `D:\ROS2Course\ssh\id_ed25519_v2.pub` —— 贴到 GitHub 的那一行
> - 旧密钥 `id_ed25519`（PowerShell 那次误带了密码，已弃用）不用管，git 已指向 v2。
> - 仓库配置 `.git/config` 里的 `core.sshCommand` 已指向私钥（不含密码，本机专用）

> 📌 如果建仓时勾了 `Add a README file`，远程会多一个初始提交，首次 push 被拒（non-fast-forward）。
> 一键脚本会自动 `fetch + merge --allow-unrelated-histories` 重试；手动跑就补一句：
> `git pull origin main --allow-unrelated-histories --no-edit` 然后重新 `git push`。

## 三、常用 Git 命令（以后天天用）

| 场景 | 命令 |
|---|---|
| 看状态 | `git status` |
| 暂存全部改动 | `git add -A` |
| 提交 | `git commit -m "描述这次改了啥"` |

## 四、踩了什么坑

- [ ] **坑 1：push 要输密码** —— 用 **SSH 地址**（`git@github.com:...`）而不是 HTTPS，配好 key 后免密。
- [ ] **坑 2：`git init` 建错目录** —— 在课程根目录 init，别在子文件夹（否则只提交了一个 Day）。
- [ ] **坑 3：把编译产物传上去** —— `build/ install/ log/ __pycache__/` 必须被**根目录**的 `.gitignore` 忽略；
  放在 `模板/` 里是不生效的，脚本会帮你拷到根目录。
- [ ] **坑 4：commit 前没 add** —— 改了不 `add` 就 `commit`，什么都没存进去。
- [ ] **坑 5：username 没想好** —— GitHub 用户名难改，注册时定好。
- [x] **★ 坑 6：`Please tell me who you are`** —— 本机 Windows / WSL 都没有全局 `.gitconfig`。
  已在本仓库配好**仓库级**身份；脚本现在读的是「最终生效值」（不带 `--global`），
  所以全局或 `--local` 任一处配过都放行，不会误拦。
- [x] **★ 坑 7：首次 push 被拒（non-fast-forward）** —— 建仓时勾了 `Add a README file`。
  保持空仓库即可避开；脚本已加自动 `fetch + merge` 兜底。
- [x] **★ 坑 8：`C:\Users\MicckeY\.ssh` 连普通终端都建不了** —— 不仅 agent，用户自己的 PowerShell 跑 `ssh-keygen` 也报
  `Could not create directory ... Permission denied`。**根因是 Home 目录整体无写权限**，不是 agent 的问题。
  绕过方案：密钥生成到 `D:\ROS2Course\ssh\`，再用仓库级 `core.sshCommand` 指向它（已配好）。
  ⚠️ 另一个真实踩坑：在 `Enter file in which to save the key` 提示处**误贴了仓库地址**
  （`git@github.com:...`）当文件名 → `Saving key ... failed: No such file or directory`。
  记住：**仓库地址只给 `git push` 用；ssh-keygen 的三个提示全部直接回车**。
- [x] **★ 坑 8b：私钥带了密码，push 每次问 `Enter passphrase`** —— PowerShell 调 `ssh-keygen -N ""` 时空字符串被吞，
  结果生成了**带密码**的私钥，push 时输不对 → `Permission denied (publickey)`。
  排查：`ssh-keygen -y -P "" -f <私钥>` 能导出公钥才是真空密码。
  已用 bash `-N ""` 重生成 `id_ed25519_v2` 并验证无密码，git 的 `core.sshCommand` 指向它（加 `IdentitiesOnly=yes`）。
- [x] **★ 坑 9：Windows git 把 `.sh` 换行改成 CRLF** —— `git add` 时报一片
  `LF will be replaced by CRLF`，下次 checkout 后 WSL 会报 `\r: command not found`。
  已加根目录 `.gitattributes`（`* text=auto eol=lf`）强制 LF，警告全部消失。
- [ ] **坑 10：`ssh -T git@github.com` 超时** —— 有些网络封了 22 端口，改走 443：
  在 `~/.ssh/config` 里写 `Host github.com` / `HostName ssh.github.com` / `Port 443` / `User git`。
- [ ] **坑 11：WSL 里 `dubious ownership`** —— 见上面第 3 步的 `safe.directory` 一行。
