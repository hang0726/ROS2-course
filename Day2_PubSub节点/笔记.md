## 一、今天学了什么

### 1. 话题（Topic）通信模型
话题是**多对多、单向**的数据管道：发布者往话题上"喊"，订阅者从话题上"听"，两者互不认识、靠**话题名 + 消息类型**配对。
```
Talker ──publish──>  /chatter(String)  ──>  Listener.on_msg()
```
- 发布者：`create_publisher(消息类型, 话题名, QoS)`
- 订阅者：`create_subscription(消息类型, 话题名, 回调, QoS)`

### 2. 完整可运行演示（合并版，开两个终端跑）
```bash
source /opt/ros/humble/setup.bash
cd /mnt/d/ROS2七天速成/Day2_PubSub节点

# 终端1：发布者，每 0.5s 发一条递增字符串
python3 pub_sub_demo.py talker
# 终端2：订阅者，打印收到的内容
python3 pub_sub_demo.py listener
```
> 订阅者持续打印 `收到: "你好，这是第 N 条"`，就跑通了。

### 3. 官方教程标准写法（拆成两个文件 + 包）
官方把节点放进一个 **package**（Colcon 工作空间），Day3 会正式建包；今天先把两个节点文件写好，理解骨架：
- `模板/publisher_member_function.py` —— 发布者（定时发 `std_msgs/String`）
- `模板/subscriber_member_function.py` —— 订阅者（收并打印）

### 4. 关键 API 速记
| 动作 | 代码 | 说明 |
|---|---|---|
| 建节点 | `class X(Node)` + `super().__init__('名字')` | 名字全局唯一 |
| 发消息 | `self.pub.publish(msg)` | 在定时器回调里调 |
| 收消息 | `def on_msg(self, msg): ...` | 有新消息自动触发 |
| 定时触发 | `self.create_timer(0.5, self.cb)` | 每 0.5s 调一次 cb |
| 转起来 | `rclpy.spin(node)` | 阻塞处理回调 |

## 二、踩了什么坑

- [ ] **坑 1：没 source** —— `import rclpy` 报 `ModuleNotFoundError`，先 `source /opt/ros/humble/setup.bash`。
- [ ] **坑 2：话题名/类型不一致** —— 发布者用 `/chatter`+`String`，订阅者也必须一致，否则**静默收不到**（不报错）。用 `ros2 topic list` / `ros2 topic info /chatter -v` 核对。
- [ ] **坑 3：忘了 `rclpy.spin()`** —— 没 spin 节点直接退出，定时器/回调根本不触发。
- [ ] **坑 4：QoS 不匹配** —— 双方 QoS 策略不一致会收不到；初学用默认 `10` 即可。
- [ ] **坑 5：两个终端都跑成 talker** —— 一个 talker 一个 listener，别两个都发。
- [ ] **坑 6：IDE 里 `import rclpy` 冒黄色波浪线** —— 这是编辑器静态检查"找不到包"（IDE 解释器是 Windows Python，而 rclpy 在 WSL 的 `/opt/ros/humble/lib/python3.10/site-packages`），**黄色是 warning，不影响 WSL 里 `python3` 运行**。要消黄：VSCode 用 Remote-WSL 打开（本课程根目录已配 `.vscode/settings.json`）；PyCharm 用 WSL 解释器 + 加该路径。🚫 **别在 Windows IDE 里点"运行"**（Windows 没 rclpy 必报错），一律在 WSL 终端跑。
