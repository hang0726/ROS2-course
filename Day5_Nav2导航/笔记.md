## 一、今天学了什么

### 0. 先确认地图在不在（Day4 已经存过了）

Day4 的 `Ctrl+C → 回车` 已经把地图存成：

```bash
ls -lh ~/tb3_map.pgm ~/tb3_map.yaml
```

`~/tb3_map.yaml` 内容大致长这样，参数合法就能被 Nav2 / AMCL 加载：

```yaml
image: tb3_map.pgm
mode: trinary

occupied_thresh: 0.65
free_thresh: 0.25
```

> ✅ **不用再存一次**。想另存一份到 `~/maps/my_map` 也可以：
> `ros2 run nav2_map_server map_saver_cli -f ~/maps/my_map`

### 1. ⚠️ 开跑前先把 Day4 全部窗口关掉

Day4 的 `slam_toolbox` 和 Day5 的 `AMCL` **都要发布 `map→odom` 这个 TF**，同一时刻只能有一个节点管它：

| 阶段 | 谁管 `map→odom` |
|---|---|
| Day4 建图 | `slam_toolbox` |
| Day5 导航 | `AMCL` |

所以按 `Ctrl+C` 退出遥控、关掉 Gazebo / RViz 终端后，再进 Day5。模板脚本会检测 `slam_toolbox` 是否还在，还在就直接拦住你。

### 2. 加载地图 + 定位 + 导航（一条 launch 搞定）

`nav2_bringup` 的仿真 launch 会一次拉起 **Gazebo 世界 + map_server + AMCL + Nav2 规划器 + RViz**：

```bash
source /opt/ros/humble/setup.bash
export TURTLEBOT3_MODEL=waffle
export DISPLAY=:0
export LIBGL_ALWAYS_SOFTWARE=1      # WSLg 防黑屏，Day4 实测必带

ros2 launch nav2_bringup tb3_simulation_launch.py \
  headless:=False \
  map:=$HOME/tb3_map.yaml \
  world:=/opt/ros/humble/share/turtlebot3_gazebo/worlds/turtlebot3_world.world
```

✅ 直接用模板脚本（已带软件渲染 + 路径检查 + SLAM 残留检测）：

```bash
bash "/mnt/d/具身智能求职培训/Day5_Nav2导航/模板/保存并导航.sh"
# 想用别的地图：bash ".../保存并导航.sh" /path/to/map.yaml
```

> 📌 `map:=` 必须是**绝对路径**且文件真实存在，否则导航栈起不来。

### 3. 在 RViz 里导航到目标点

`tb3_simulation_launch.py` **自带 RViz**，不用再另开一个（开两个反而抢话题、白占内存）。

#### ⚠️ 先搞清楚按钮叫什么（这里最容易找错）

本机 `/opt/ros/humble/share/nav2_bringup/rviz/nav2_default_view.rviz` 的 `Tools:` 段实测顺序：

| 序号 | 工具 | 作用 |
|---|---|---|
| 1–4 | MoveCamera / Select / FocusCamera / Measure | 视角与测量 |
| 5 | `2D Pose Estimate`（`SetInitialPose`） | 发 `/initialpose`，给 AMCL 初始位姿 |
| 6 | `Publish Point` | 发 `/clicked_point` |
| **7（最右）** | **`GoalTool`（`nav2_rviz_plugins/GoalTool`）** | **发 `/navigate_to_pose` action，让机器人真的走** |

⚠️ **这份配置里没有 `2D Goal Pose` 这个按钮**（没加载 `rviz_default_plugins/SetGoal`）。就算手动加出来，它发的也是 `/goal_pose` topic，Nav2 **不认**，点了机器人不会动。

**所以：找工具栏最右边那个按钮**，紧挨在 `Publish Point` 右边；鼠标悬停看 tooltip，名字显示为 `GoalTool` / `Nav2 Goal`，描述是 "A tool used to specify the navigation goal pose."，绿色箭头/旗子图标。

- 工具栏被窗口挤窄、按钮被折叠了 → 点最右侧的 **`+`**（Add Tool），在列表里勾上 `GoalTool`
- 也可以试试快捷键 **`G`**
- 实在找不到：把鼠标依次停在最右几个图标上，看 tooltip 描述

#### 操作步骤

1. **先给初始位姿**：点 `2D Pose Estimate`（工具栏第 5 个），在地图上小车**实际所在位置**点一下、拖一下箭头设朝向。AMCL 靠它初始化，不给就报「无初始位姿」。
2. **下发目标**：点**工具栏最右侧的 `GoalTool` / `Nav2 Goal`**，在地图**空旷处**点一下、拖箭头设朝向。
3. 看机器人自己规划出**绿色路径**，绕过障碍走到目标。

> 📌 点一下地图 = 下发一个 `NavigateToPose` action 目标（等价 Day6 里你用 Python 发的那个目标）。

### 4. 关键包/命令速记

| 动作 | 命令 / 包 |
|---|---|
| 保存地图 | `ros2 run nav2_map_server map_saver_cli -f ~/tb3_map` |

## 二、踩了什么坑

- [ ] **坑 1：忘了保存地图** —— 直接关节点图就没了；Day4 务必 `Ctrl+C` 后回车存成 `.pgm + .yaml`。
- [ ] **坑 2：导航报「无初始位姿」** —— AMCL 没初始化；先在 RViz 用 `2D Pose Estimate` 给个初始位姿。
- [ ] **坑 3：地图路径写错** —— 旧版笔记写 `~/maps/my_map.yaml`，但 Day4 实际存的是 **`~/tb3_map.yaml`**；`map:=` 要绝对路径且文件存在。
- [ ] **坑 4：目标点设在障碍物里** —— 机器人规划失败；点空旷处。
- [ ] **坑 5：`DISPLAY` 没设 / 3D 窗口全黑** —— 同 Day4，WSLg 必须带 `LIBGL_ALWAYS_SOFTWARE=1` + `GALLIUM_DRIVER=llvmpipe`；模板脚本已默认带。
- [ ] **坑 6：Day4 没关干净** —— `slam_toolbox` 与 AMCL 抢 `map→odom`，定位乱跳；先关全部 Day4 窗口。
- [ ] **坑 7：重复开 RViz** —— bringup 自带 RViz，别再手动 `ros2 run rviz2`。
- [ ] **坑 8：脚本开了 `set -u`** —— `source /opt/ros/humble/setup.bash` 会因 `AMENT_TRACE_SETUP_FILES` 未定义直接退出（Day4 实测踩过）。
- [ ] **坑 9：满世界找 `2D Goal Pose`** —— 这份 RViz 配置里没这个工具；要用**工具栏最右侧的 `GoalTool`/`Nav2 Goal`**，它才发 Nav2 认的 action。
- [ ] **坑 10：点了目标小车不动** —— `tb3_simulation_launch.py` 默认世界是 `nav2_bringup/worlds/world_only.model`，**和 Day4 建图用的 `turtlebot3_world.world` 不是同一个**！激光与地图对不上，AMCL 收敛不了、代价地图全是未知 → 规划失败。必须加 `world:=.../turtlebot3_gazebo/worlds/turtlebot3_world.world`（模板脚本已带）。
  另外按顺序自查：① 是否先给了 `2D Pose Estimate`（不给 AMCL 不工作）② 底部 Nav2 面板是否从 `unknown` 变 active ③ 目标点是否在空旷处 ④ Day4 的 Gazebo 是否还残留（两个 gzserver 会冲突，19:01 那次日志里 `gzserver exit 255` 就是这个）。
