## 一、三个节点分别干什么

| 节点文件 | 通信方式 | 话题 / Action | 用途 |
|---|---|---|---|
| `send_nav_goal.py` | **Action 客户端** | `/navigate_to_pose` | 给 Nav2 发目标位姿，机器人自主导航过去 |
| `odom_subscriber.py` | **话题订阅** | `/odom`（本机实测） | 实时读机器人位置与速度 |
| `velocity_commander.py` | **话题发布** | `/cmd_vel` | 直接下发速度指令让机器人动（最底层控制） |

> 关系：**里程计**是"我在哪、走多快"（传感器反馈）；**速度指令**是"我想怎么动"（执行器命令）；
> **导航目标**是"我要去哪"（高层任务，由 Nav2 拆成速度指令去执行）。

### 重点学这四件事
1. **导航是 Action 不是话题**：用 `ActionClient` 连 `/navigate_to_pose`，带"是否被接受 / 实时反馈 / 最终结果"三套回调（`send_nav_goal.py`）。
2. **目标位姿在 `map` 坐标系**：`frame_id='map'`；yaw 朝向要转成四元数（绕 z 轴公式，`_yaw_to_quat`）。
3. **里程计字段**：`msg.pose.pose.position`（位置）+ `msg.twist.twist`（速度），类型 `nav_msgs/Odometry`（`odom_subscriber.py`）。
4. **速度指令 Twist**：差速车只用 `linear.x`（前进）+ `angular.z`（转向），发到 `/cmd_vel`（`velocity_commander.py`）。

## 三、踩了什么坑（★ = 今天已经帮你修掉的）

- [x] **★ 坑 0：里程计一条都不打印** —— 旧版默认订阅 `/odometry`，但本机 TB3 的 `model.sdf` 写死
  `<odometry_topic>odom</odometry_topic>`，实际只有 `/odom`。默认已改成 `/odom`，并加「5 秒无数据」告警 + 日志限流 2Hz。
- [x] **★ 坑 0.5：目标被拒后程序卡死** —— 旧版 `goal_response_cb` 里 `accepted=False` 只 `return`，
  `rclpy.spin` 永远不退出。已补 `rclpy.shutdown()`；`wait_for_server` 也加了 10 秒超时，
  没起 Day5 栈会明确报错而不是干等。
- [x] **★ 坑 0.8：Ctrl+C 后车还在冲** —— `velocity_commander.py` 现在正常结束和 Ctrl+C 都会
  走 `stop()` 补发全 0 速度；自己改逻辑务必保留这一步。
- [ ] **坑 1：导航目标被拒绝** —— 多半是没给 AMCL 初始位姿（Day5 的 `2D Pose Estimate`）或没地图；先 RViz 给位姿再发。
  ★ 2026-11-15 实跑实证：Nav2 侧会每 2.5 秒刷 `[WARN] [amcl]: AMCL cannot publish a pose or update the transform. Please set the initial pose...`，
  看到这条就说明 **RViz 里没点 2D Pose Estimate**（注意不是 `Nav2 Goal`）。点了之后警告停止、粒子云出现，再发目标就会被接受。
  自查：`ros2 topic echo /amcl_pose --once` 有位姿输出才算定位生效。
- [ ] **坑 2：话题名不对** —— `ros2 topic list | grep -E 'odom|cmd_vel'` 自查，把真实名字当参数传给节点②。
- [ ] **★ 坑 3：跑节点③时车抽风** —— Nav2 的 `controller_server` 在**导航进行中**也会发 `/cmd_vel`，
  跟你的节点抢同一个话题。等导航结束（或在 RViz 取消目标）再跑节点③；Nav2 空闲时是安全的。
- [ ] **坑 5：yaw 朝向搞反** —— 四元数只填 z/w（平面导航够用），别把 x/y 也填了。
- [ ] **坑 6：世界 / 地图不匹配** —— 沿用 Day5 的 `world:=turtlebot3_world.world`，别换回
  `world_only.model`，否则激光和地图对不上、AMCL 不收敛、车不动。
