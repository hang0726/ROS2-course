## 三、昇腾 AI 栈心智模型（★ 今天最该记住的）

```
训练侧（PC/云，MindSpore/PyTorch）──导出 ONNX/AIR ─→ ATC 转换 ─→ .om 模型 ─→ 车上 AscendCL(C++) 推理
```

| 名字 | 是什么 | 类比 NVIDIA 的 | 别搞混 |
|---|---|---|---|
| **CANN** | 昇腾底层驱动+工具链（含 ATC、AscendCL） | CUDA + TensorRT 工具链 | 不是框架，是"底座" |
| **MindSpore** | 华为 AI 框架 | PyTorch | 训练用，车上推理一般不直接用它 |
| **ATC** | 模型转换工具 | TensorRT 的模型编译 | ONNX/AIR → .om |
| **AscendCL** | C/C++ 推理接口 | TensorRT C++ API | 你写 C++ 加载 .om 推理就靠它 |
| **.om** | 昇腾离线模型格式 | .engine（TensorRT） | ATC 转出来，车上只能跑这个 |

🔴 **最容易踩的坑**：`atc` 转换时 `--soc_version` 必须写 **`Ascend310B`**（你这块芯片）。写错 → 转出的 .om 车上加载失败。

# 【待材料：学校指导书给的 CANN 版本与安装包路径】

### 步骤 3 · 装 AI 框架（官方实验 16-18）
```bash

```

### 步骤 4 · 跑通一次 ATC 模型转换（官方实验 19，可先跟官方样例）
用昇腾官方开源样例库里的 ResNet50 走一遍转换全流程（真链接见总纲第七节）：
```bash
git clone https://gitee.com/ascend/samples.git
# 样例里有 resnet50 分类完整代码 + ATC 转换命令
atc --model=resnet50.onnx --framework=5 --output=resnet50_ascend \
    --soc_version=Ascend310B --input_shape="input:1,3,224,224"
```
✅ 转出 `.om` 文件 = 环境通了。这同时也是你 **C++ 缺口**的入口（AscendCL 样例是 C++）。

### 步骤 5 · 环境自检（本目录实例代码）
```bash
python3 ascend_env_check.py     # 检查 CANN/MindSpore/ROS2/NPU 是否就绪
```
本目录 `ascend_env_check.py` 会逐项打印"通/缺"，缺什么一目了然。

## 五、今天踩坑（预置，遇到打勾）

- [ ] **`npu-smi` 找不到** —— 驱动没装好或环境变量没 source；`source set_env.sh` 后重试。
- [ ] **ATC 转换报 `soc_version` 错** —— 必须是 `Ascend310B`，别写 Ascend310/310P。
- [ ] **MindSpore import 失败** —— 装的是 x86 版不是昇腾版；用官方昇腾 wheel。
- [ ] **ATC 版本和 CANN 不匹配** —— 版本要对应，升级/降级到一致。
- [ ] **ROS2 和昇腾环境变量打架** —— 两个 setup.bash 都要 source，注意顺序和覆盖。
