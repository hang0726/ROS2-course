## 一、导航三件套（回顾 Day5，真机一样）

1. **地图**：Day10 存的 `.yaml` + `.pgm`
2. **AMCL 定位**：用雷达 + 地图算"车在哪"
3. **Nav2 导航**：给目标点，规划路径，控制车走过去

🔴 **TF 所有权互斥**（你 Day4/Day5 踩过的坑，真机一样）：
- Day10 的 `slam_gmapping` 和今天的 `AMCL` **都在发 `map→odom`**——同一时刻只能有一个。
- **今天起 AMCL 前，先确认建图节点已关掉**，否则 TF 打架、车乱跑。

## 二、今天做什么

### 步骤 1 · 起导航栈
```bash
# 命令行
ros2 launch chuyun_navigation2 lite_navigation.launch.py map:=/root/chuyun_ws/src/chuyun_navigation2/maps/my_room.yaml
# 或网页中控台：Day8 页面点「开始导航」（配置在 ros_config.json 的 tasks.navigation）
```
🔴 真机用 `chuyun_navigation2`（网页默认 Lite 引擎，可切 Nav2），**不是**仿真的 `nav2_bringup tb3_simulation_launch.py`。

### 步骤 2 · 给初始位姿（★ 不做这步，目标必被拒）
在 RViz 或中控台点 **`2D Pose Estimate`**（不是"2D Goal Pose"，你 Day5 纠正过），
在地图上小车实际位置拖出朝向箭头。

> ⚠️ 你 Day6 第一次失败就是没给初始位姿：AMCL 日志一直刷 `Please set the initial pose`，bt_navigator 直接拒目标。**今天别忘。**

等粒子云收敛：`ros2 topic echo /amcl_pose --once` 有稳定数值。

### 步骤 3 · 发导航目标
点 **`Nav2 Goal`**（你 Day5 认过的真按钮），在地图上拖一个目标点。
✅ 车规划路径 → 走过去 → 到达。

### 步骤 4 · 复用你写的节点（选做，Day6 三节点）
```bash
python3 send_nav_goal.py 0.5 0.0 0.0    # 注意别用 1.0，可能越出地图边界（Day6 的坑）
python3 odom_subscriber.py
```
⚠️ 速度节点 `velocity_commander.py` 和 Nav2 都发 `/cmd_vel`，**不要同时跑**。

## 三、今天踩坑

- [ ] **目标被拒（状态码 6 / ABORTED）** —— 先给 2D Pose Estimate；目标别越出地图边界。
- [ ] **TF 打架、车乱转** —— 建图的 `slam_gmapping` 没关，和 AMCL 抢 `map→odom`。
- [ ] **车原地打转不走** —— AMCL 初始位姿给错了方向；重新给。
- [ ] **规划失败 `goal off costmap`** —— 目标点在地图外（Day6 的 x=1.0 越界坑）；换地图内的点。
- [ ] **地图加载失败** —— `.yaml` 里 image 路径不对；确认 `.pgm` 和 `.yaml` 在同一目录。
