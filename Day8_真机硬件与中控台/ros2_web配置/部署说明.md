# ros2_web 网页中控台 · RK3528 配置指南

> 🎯 **目标**：在你的 RK3528 进阶版小车上跑起网页中控台，浏览器打开 `http://<车IP>:5173` 就能建图、导航、摇杆控制。
> 仓库：`https://github.com/czu963889306-dev/ros2_web` —— 分 `Ros_Vue_arm`（你的车，ARM）和 `Ros_Vue_x86`（PC/x86）两个版本。**你只用 ARM 版**。

---

## ⚠️ 先读这段（决定成败）

这个中控台**不是普通网页项目**，它深度依赖卖家镜像里的三样东西：

| 依赖 | 位置 | 作用 |
|---|---|---|
| ROS2 工作空间 ×3 | `/root/chuyun_ws`、`/root/slam_ws`、`/root/nav2_ws` | 底盘/建图/导航节点 |
| Node.js + npm | 系统里（建议 v18+） | 跑前端 Vue + 后端 Express |
| `foxglove_bridge` | `ros-humble-foxglove-bridge` 包 | 网页↔ROS2 的 WebSocket 桥（端口 8765） |

**结论：优先用卖家给进阶版（RK3528）的现成镜像**，这三样都预装好了。
自己从零装 = 要凑齐三个工作空间 + TF2 兼容库，坑极多。**除非卖家镜像出问题，否则别自己搭。**

> 🔴 关于卖家镜像来源：见 `Day8_真机硬件与中控台/资料索引.md` —— 进阶版镜像在卖家的网盘/B站简介里，按视频 `[1-1] 安装教程` 烧录。

## 一、两条路线（先选一条）

| 路线 | 适用 | 工作量 |
|---|---|---|
| **A. 卖家镜像已装好中控台** | 镜像自带 ros2_web | 只 clone/更新 + 改配置，10 分钟 |
| **B. 镜像有 ROS2 但没中控台** | 工作空间在，网页工具没装 | clone 仓库 + 装 Node 依赖，20 分钟 |

> 下面步骤两条路线通用，从步骤 1 开始做，卡在哪看对应说明。

## 二、部署步骤（在车上执行，SSH 进去）

### 步骤 0 · 上车 + 确认环境
```bash
ssh <用户名>@<车IP>          # 通常 root@<车IP>
source /opt/ros/humble/setup.bash

# 确认三样依赖在不在（关键！）
ls -d /root/chuyun_ws/install /root/slam_ws/install /root/nav2_ws/install 2>/dev/null
node --version                # 应 v18+
ros2 pkg list | grep foxglove_bridge
```
- 三个 `install` 目录都在 → 走路线 A
- Node 报 `command not found` → 先装：`sudo apt install -y nodejs npm`（或按卖家镜像的 NVM 方式）
- 没有 foxglove_bridge → `sudo apt install -y ros-humble-foxglove-bridge`

### 步骤 1 · 拉仓库（ARM 版）
```bash
cd /root
# 若已有旧目录，先备份更新：
# mv ros2_web ros2_web.bak_$(date +%Y%m%d)
git clone https://github.com/czu963889306-dev/ros2_web.git
cd ros2_web/Ros_Vue_arm
```
> 目录放 `/root/ros2_web/Ros_Vue_arm` 是因为启动脚本和配置里的路径都按这个位置写死的。
> 如果你放别处，`ros_config.json` 里 `/root/ros2_web/foxglove_bridge.params.yaml` 要改成实际路径。

### 步骤 2 · 替换配置（用我给你的文件）
把本目录的两个文件上传到车：
```bash
# 在你 Windows 侧 PowerShell 执行（换成你的车 IP 和用户名）
scp "D:\具身智能求职培训\Day8_真机硬件与中控台\ros2_web配置\ros_config.json" root@<车IP>:/root/ros2_web/Ros_Vue_arm/ros_config.json
scp "D:\具身智能求职培训\Day8_真机硬件与中控台\ros2_web配置\foxglove_bridge.params.yaml" root@<车IP>:/root/ros2_web/foxglove_bridge.params.yaml
```
> 注：`ros_config.json` 里写死的 params 路径是 `/root/ros2_web/foxglove_bridge.params.yaml`（在 `Ros_Vue_arm` 的**上一层**），别传错位置。

> 如果你要保留卖家原版：`cp ros_config.json ros_config.json.orig` 先备份。

### 步骤 3 · 启动
```bash
cd /root/ros2_web/Ros_Vue_arm
bash start_console.sh
```
看到输出：
```
本机访问地址: http://localhost:5173
外部设备访问: http://<车IP>:5173
Automatic startup triggered.
```
就成功了。

### 步骤 4 · 浏览器打开
电脑连同一个 WiFi，浏览器开 `http://<车IP>:5173`。
顶部显示"已连接" = Foxglove Bridge 通了；能看到地图区、摇杆、电池状态就齐了。

## 三、配置里到底改了什么（对照原版）

我给你的 `ros_config.json` 基于仓库**当前真实版本**（2026-10 更新），关键点：

| 项 | 值 | 说明 |
|---|---|---|
| 建图默认 | `slam_toolbox` | 网页上还能切 Cartographer / Gmapping（弹窗选） |
| 导航默认 | `lite` | 还能切 Nav2；差速/麦轮也能选 |
| Foxglove 话题 | `/web/tf`、`/web/odometry/filtered` | **降频版**，省 RK3528 的 CPU；控制仍用原始 `/tf` `/odom` |
| 电池 | `/battery_state` | `sensor_msgs/BatteryState`，不是旧的 `/battery` |
| 地图目录 | `/root/chuyun_ws/src/chuyun_navigation2/maps` | 和 Day10 建图存图路径要一致 |
| 摄像头 | `/stream` + 8080 端口 | MediaMTX WebRTC，也支持 MJPEG |

🔴 **和我教材里旧写的差异**（以这份真实配置为准）：
- 导航包名是 `chuyun_navigation2`（不是 `xuegecar_navigation2`）
- 建图默认 `slam_toolbox`（不是 `slam_gmapping`，但网页可切换）

## 四、踩坑（遇到再查）

- [ ] **启动报"缺少工作空间安装环境"** —— `/root/chuyun_ws/install/local_setup.bash` 等三个文件缺；说明镜像不对，回步骤 0 换卖家 RK3528 镜像。
- [ ] **`command -v node` 失败** —— 装 Node.js v18+。
- [ ] **网页不显示"已连接"** —— Foxglove Bridge 没起来；`ros2 run foxglove_bridge foxglove_bridge --ros-args --params-file /root/ros2_web/foxglove_bridge.params.yaml` 手动测。
- [ ] **浏览器打不开** —— 车和电脑不同 WiFi；`hostname -I` 看车实际 IP；端口 5173 被占换 `--strictPort` 会报错。
- [ ] **换了 WiFi IP 变了** —— 网页顶部能看到新 IP，用新 IP 访问；或用有线地址 `http://192.168.2.2:5173`。
- [ ] **《导航 TF2 死锁》** —— 卖家新版已带 `tf2_compat_0_25_22` 兼容库，别自己乱升 TF2。
- [ ] **停了中控台网页断线** —— SSH 执行 `bash /root/ros_service_ctl.sh start ros2-web` 恢复。
