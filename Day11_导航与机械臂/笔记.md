## 二、两块核心内容

### A. 路点导航（官方实验 31）
和旧小车 Day5 的 Nav2 Goal 一脉相承，但这台车多一个玩法：**多航点巡检**。

| 概念 | 作用 |
|---|---|
| 单目标导航 | 给一个点，走过去（Action `/navigate_to_pose`） |
| **FollowWaypoints** | 给一串点，依次走Complete（Action `/follow_waypoints`） |
| 动态避障 | 导航中遇到移动障碍物绕开 |

🔴 **TF 所有权互斥**（老坑，新车一样）：建图节点和 AMCL 都发 `map→odom`，不能同时跑。

### B. MoveIt 机械臂 + 手眼标定（官方实验 24/26/29，★ 新平台核心）

**MoveIt2** = ROS2 里控制机械臂的标准框架：

```
给目标位姿 → MoveIt 做运动学求解(IK) → 轨迹规划(避碰) → 驱动六轴到目标
```

**手眼标定**（官方实验强调的难点）= 求"相机坐标系"和"机械臂坐标系"的相对关系：
```
AX = XB    # A=相机运动, B=机械臂运动, X=要求的变换
```
- **Eye-in-Hand**：相机装在手上 → 求 camera→end_effector
- **Eye-to-Hand**：相机装外面 → 求 camera→base

🔑 标定了这个，"像素坐标 (u,v)" + "深度 d" 才能变成"机械臂要去的三维坐标 (x,y,z)"——
这是 Day12 视觉引导抓取的前提。

## 四、今天踩坑（预置）

- [ ] **目标被拒** —— 没给 2D Pose Estimate / 目标越界。
- [ ] **TF 打架** —— 建图和 AMCL 同时跑，抢 `map→odom`。
- [ ] **MoveIt 规划失败** —— 目标位姿超出工作空间 / 有碰撞；换姿态重试。
- [ ] **机械臂不动** —— 没上电/使能，或急停没松。
- [ ] **手眼标定误差大** —— 标定板姿态采样不够（至少 15-20 组），或相机内参不对。
