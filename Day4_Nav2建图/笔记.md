# Day 4：Nav2 建图 · SLAM Toolbox 跑通

> 🎯 **今日目标**：跑通 **SLAM 建图**——让 TurtleBot3（TB3）在 Gazebo 里走一圈，实时生成一张栅格地图，并**保存成 `pgm + yaml`** 交给 Day5 导航用。
> 标准学习路线：**TurtleBot3 仿真（Gazebo）+ slam_toolbox**。无实物也能学。
>
> ✅ **本机**：Day1 已装 ROS2 Humble，但 TB3 / Gazebo / SLAM 是**另外的包**，今天装一次（第 2 节）。
> ⚠️ 今天开始要开**图形界面**（Gazebo + RViz）。Win11 自带 **WSLg**，不用再装 VcXsrv；若黑屏见「坑 1」。

## 一、今天学了什么

### 1. 整体链路
```
Gazebo 仿真(TB3)  ──话题──>  /scan(激光) + /odom(里程计) + /tf
                                   │
                             slam_toolbox
                                   │
                                /map  (实时栅格地图)  ──>  rviz2 可视化
```
**SLAM = 同时定位与建图**：机器人一边用激光/里程计估计「我在哪」，一边把环境画成地图。

### 2. 装包（只装一次，约 1~2 GB）
```bash
source /opt/ros/humble/setup.bash
sudo apt update
sudo apt install -y \
  ros-humble-turtlebot3 \
  ros-humble-turtlebot3-gazebo \
  ros-humble-turtlebot3-teleop \
  ros-humble-slam-toolbox \
  ros-humble-nav2-bringup \
  ros-humble-navigation2
```
| 包 | 作用 |
|---|---|
| `turtlebot3` | 机器人模型/描述 |
| `turtlebot3-gazebo` | Gazebo 世界 + 仿真启动文件 |
| `turtlebot3-teleop` | 键盘遥控（`teleop_keyboard`） |
| `slam-toolbox` | **今天的核心：建图** |
| `nav2-bringup` / `navigation2` | Day5 导航用（顺带装好，RViz 配置也从这里来） |

### 3. 四个终端跑起来（★ 正确做法）
**每个终端先统一设置**（嫌麻烦就写进 `~/.bashrc` 末尾，一次到位）：
```bash
source /opt/ros/humble/setup.bash
export TURTLEBOT3_MODEL=waffle        # ★★★ 不设这个，TB3 节点直接报错退出
export GAZEBO_MODEL_PATH=$GAZEBO_MODEL_PATH:/opt/ros/humble/share/turtlebot3_gazebo/models
```

**终端 1 — 起 Gazebo 世界（只仿真，不带定位）**
```bash
ros2 launch turtlebot3_gazebo turtlebot3_world.launch.py
```
> 或直接 `bash 模板/启动建图.sh`（它会做自检 + 打印另外两个终端要跑的命令）。

**终端 2 — 起 SLAM 建图**（`use_sim_time:=true` 必加，见坑 4）
```bash
ros2 launch slam_toolbox online_async_launch.py use_sim_time:=true
```

**终端 3 — 只看地图（RViz 窗口）**
```bash
ros2 run rviz2 rviz2 -d /opt/ros/humble/share/nav2_bringup/rviz/nav2_default_view.rviz
```
> 这个窗口**只用来看** `/map` 一点点长出来，不接受开车按键。

**终端 4 — 键盘遥控（★ 按键在这个窗口按）**
```bash
ros2 run turtlebot3_teleop teleop_keyboard
```
```
        w          w / x : 增 / 减 前进速度
   a    s    d     a / d : 增 / 减 转向速度
        x          s 或空格 : 急停       CTRL-C : 退出
```
> ⚠️ **`rviz2` 是前台进程、会占住终端不返回**，所以 RViz 和遥控**必须各开一个终端**，别把两条命令塞进同一个。
> ⚠️ **按键前先点一下终端 4 的窗口让它有焦点**；焦点在 RViz / Gazebo 窗口时按 `w` 没反应。
> ⚠️ `w` 不是「走一步」，是**把速度调高一档**，车会一直走；要停按 `s`。
> RViz 工具栏里的导航目标按钮是 **Day5 起 Nav2 后**才生效，Day4 建图阶段按了没反应。注意：本机这份 RViz 配置里**没有** `2D Goal Pose` 按钮，真正发导航目标的是**工具栏最右侧的 `GoalTool` / `Nav2 Goal`**（详见 Day5 笔记）。

> 📌 让车 **慢且匀速** 地走，贴边走一圈；原地打转会把地图「糊」掉。走完一圈，RViz 里 `/map` 就成型了。

### 4. ★ 为什么 Day4 **不能**用 `nav2_bringup` 的 `tb3_simulation_launch.py`
`nav2_bringup/tb3_simulation_launch.py` 会**连 AMCL 定位一起启动**，而 AMCL 也在发 `map → odom` 这个 TF；
`slam_toolbox` 建图时**同样**在发 `map → odom` → 两条 TF 打架，地图抖、RViz 报 TF 错。
- **Day4（建图）**：`map→odom` 由 **slam_toolbox** 拥有 → 用 `turtlebot3_gazebo` 只起世界。
- **Day5（导航）**：`map→odom` 由 **AMCL** 拥有（用今天存的地图）→ 那时才用 `nav2_bringup`。
一句话：**一个时刻只能有一个节点管 `map→odom`。**

### 5. 保存地图（Day5 导航要用）
地图建好后（车走完一圈），在任意已 source 的终端：
```bash
ros2 run nav2_map_server map_saver_cli -f ~/tb3_map
# 生成 ~/tb3_map.pgm（图） + ~/tb3_map.yaml（分辨率/原点等元数据）
```
> 或 `bash 模板/保存地图.sh`（默认存到 `~/tb3_map`，也可传路径参数）。

## 二、踩了什么坑

- [ ] **坑 1：Gazebo 黑屏 / 起不来** —— Win11 用 WSLg，先 `echo $DISPLAY`（一般已是 `:0` 之类，有值就说明有图形）。仍黑屏就试 `export LIBGL_ALWAYS_SOFTWARE=1` 再跑（软件渲染兜底）。**实在太卡/黑屏修不好 → Day4 是切 VM 的最佳时机**（VMware + Ubuntu22.04 桌面，原生 GUI）。
- [ ] **坑 2：忘了 `TURTLEBOT3_MODEL`** —— 不设这个变量，TB3 节点直接报错退出。写进 `~/.bashrc` 最省心。
- [ ] **坑 3：误用 `nav2_bringup` 起 AMCL** —— 和 slam_toolbox 抢 `map→odom`，地图抖 / RViz 报 TF。Day4 不要起 AMCL（见第 4 节）。
- [ ] **坑 4：`use_sim_time` 没开** —— 仿真时间与系统时间不一致，TF 报 `extrapolation`、地图不更新；slam_toolbox 启动时加 `use_sim_time:=true`。
- [ ] **坑 5：建图不扫全 / 地图糊** —— 遥控太快或原地打转；慢走、贴边走一圈。
- [ ] **坑 6：保存地图找不到文件** —— `-f` 一定要给**绝对路径或 `~/`**（如 `~/tb3_map`），别只写个名字，否则落在不确定的 cwd。
- [ ] **坑 7：包名记错** —— Humble 里是 `slam_toolbox` / `turtlebot3_gazebo` / `nav2_bringup`（不是老教程里的 `gmapping`）。
- [ ] **坑 8：RViz 和遥控塞进同一个终端** —— `rviz2` 占住终端不返回，第二条命令根本不执行，看起来像「遥控没反应」；两者各开一个终端，按键前确认焦点在遥控终端（见第 3 节）。
